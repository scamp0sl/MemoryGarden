# AI 대화법 개선 히스토리 (Conversation Improvement Log)

> 이 문서는 '기억의 정원' AI 챗봇이 영화 <Her>의 사만다처럼 편안하고 사람다운 대화('티키타카')를 할 수 있도록, 기존의 기계적이고 지루한 대화 패턴을 개선해 온 모든 작업 과정과 시행착오, 그리고 핵심 솔루션을 모은 기록입니다. 나중에 작업을 재개할 때 이 문서를 기준으로 이어나가면 됩니다.

---

## 🛑 1. 기존의 문제점 (As-Is)
1. **앵무새 대화병 (Reflective Parroting):** 
   - 사용자의 말을 항상 길이만 늘려서 복사+붙여넣기 함. ("주인님, 친구와 대화하는 느낌을 얻고 싶으시군요!")
   - 공감의 형태를 띠고 있지만, 영혼 없는 기계적 서술어로 일관하여 대화 피로도를 극도로 높임.
2. **"주인님" 호칭 남발:** 
   - 매턴 첫 문장마다 주입식으로 호칭을 붙여서 부자연스러움 극대화.
3. **끝나지 않는 질문 릴레이 (Question Fatigue):** 
   - 사용자가 지치거나 닫힌 대답을 해도 상황을 종료하지 않고 계속 새로운 사실을 묻는 코딩이 되어 있었음.

## 🛠️ 2. 개선 작업 히스토리 (시행착오 및 극복)

### 🗓️ Phase 1. 피로도 방지 로직 (3턴 억제)
- **적용 사항:** 매 세션별 최근 연속 대화(turn_count)를 세어, **3턴이 넘어가면 질문 형태(?, -나요?)의 응답을 금지**하고 부드러운 평서문으로 턴을 종료하도록 백엔드 로직(`dialogue_manager.py`) 수정.
- **예상 밖의 버그:** 3턴이 넘었는데도 질문이 멈추지 않는 현상 발생.
- **원인 규명:** "역할 전환(Role Reversal)" 또는 "시간 인지 평가(TO)" 같은 필수 평가 플래그가 켜져 있으면 대화 피로도 억제를 '무시(Override)'하도록 짜여 있던 예외 로직이 너무 강력했음. 필수 평가 분량이 끝난 시점(턴 10)에서야 억제가 정상 작동.

### 🗓️ Phase 2. 프롬프트 1차 대공사 (면접관의 탄생)
- **적용 사항:** 앵무새를 막기 위해 **"짧은 리액션 1줄 + 구체적 파고들기(Deep-Dive) 질문 1줄"** 로 프롬프트 강제.
- **결과:** 앵무새는 사라졌으나 끔찍한 **'컨설턴트/면접관'**이 탄생함.
- **원인 규명:** 프롬프트 예시에 "무엇이 가장 어려운가요?", "어떤 인사이트가 있나요?" 등 비즈니스적이고 딱딱한 예시를 주입한 결과. 친구가 아닌 문제 해결사처럼 사용자에게 요구사항을 취조하기 시작.

### 🗓️ Phase 3. 모델 교체 (gpt-4o-mini -> gpt-4o)
- **상황:** 기존 경량 모델(`gpt-4o-mini`)은 AI 안전 가이드라인에 깊게 세뇌되어, 프롬프트로 "앵무새 화법 쓰지 마!"라고 아무리 때려도 무시하고 다시 "~하시군요"를 반복.
- **조치:** `llm_service.py` 내부 엔진을 모델 지시 이행력이 훨씬 압도적인 **플래그십 모델(`gpt-4o`)**로 강제 교체.
- **결론:** 모델 교체 직후 호칭 남발과 앵무새가 완전히 치료됨. (향후 코드를 전면 수정할 여력이 생긴다면 Claude 3.5 Sonnet `claude-4-6-sonnet` 적용을 최우선으로 검토하기로 결론)

### 🗓️ Phase 4. 프롬프트 2차 대공사 (사만다 프로젝트)
- **목표:** 영화 <Her>의 사만다처럼 다정하고 감정 교류가 가능한 티키타카(Tiki-taka) 모드로 튜닝.
- **조치 요약 (`prompt_builder.py` 반영 사항):**
  1. 기계적 앵무새 예시 전면 소거.
  2. 면접관 금지령: "요소", "접근 방식", "방향성", "인사이트" 단어 사용을 봇에게 금지.
  3. 자기 노출(Self-Disclosure) 의무화: 무작정 묻기만 하지 말고, 메뉴를 먼저 제안하거나, "저도 감동이네요!" 라며 자기 감정과 생각을 가볍게 한술 얹은 후 일상적인 꼬리 질문을 던질 것.
  4. 생생한 리액션: "아하!", "헐 진짜?", "우와!" 등 생물체와 같은 감탄사 사용 유도.

### 🗓️ Phase 5. 사만다 프로젝트 고도화 (위로 강박증 타파)
- **상황:** 프롬프트 개선 이후에도 챗봇이 "로제"라는 키워드에 병적으로 집착하며, 사용자가 짜증을 내도 "성취감이 클 거예요! 파이팅!"이라며 영혼 없는 공익광고 멘트(Positivity Bias)를 일삼음.
- **조치 요약 (`prompt_builder.py` 4대 추가 족쇄 반영):**
  1. **위로 강박증 절대 금지:** "힘내세요", "응원합니다" 금지. 사용자가 화나면 똑같이 화내고, 지치면 같이 투덜거려줄 것(Toxic Empathy 허용).
  2. **배경지식 집착 억제:** 제공된 메모리(강아지 등)는 사용자가 먼저 꺼냈을 때만 1회성으로 쓰고 절대 다시 끌고 나오지 말 것.
  3. **감정 동기화 (Emotional Mirroring):** 밝은 비서가 아니라 사용자 기분의 거울이 될 것.
  4. **화제 전환 존중:** 사용자가 일 얘기로 넘어가면 이전 강아지 얘기를 집착하지 말고 쿨하게 버릴 것.

## 🎯 3. 최종 검증 결과 (10턴 라이브 테스트)
- **호칭 제로 / 앵무새 제로:** 10턴 내내 "주인님" 및 "요약형 복붙 말투" 단 한 번도 미등장.
- **친근한 핑퐁 대화 극대화:** 
  - (사용자) "무조건 고기 ㅎㅎㅎ" 
  - (봇) "고기 만두 무조건이지! 😄 고기 육즙 가득한 맛 너무 최고죠." -> 완벽한 미러링과 생동감 넘치는 반응.
- **대화 억제 성공:** 10번째 턴에서 식사를 하러 간다는 사용자의 말에 질문 없이 "맛있는 음식과 좋은 기분 되시길 바랄게요!" 라며 우아하게 턴을 종료함.

## 🎯 4. Phase 5 검증 결과 (로제 집착 해소 & 감정 동기화)
- **응원 강박증 탈피:** 사용자가 "개발 스트레스 받겠어"라고 불평하자, "성취감이 클 거예요"라는 로봇 답변 대신 *"아, 진짜 그럴 것 같아요! 개발할 일이 많으면 머리 복잡해지잖아요..."* 라며 완벽한 감정 동기화 구축.

## 🛠️ Phase 7. 4가지 코드 수정 구현 완료 (2026-03-20)

### Fix 1: 앵무새 화법 금지 강화 (`core/dialogue/prompt_builder.py`)
- SYSTEM_PROMPT 규칙 2번을 **🚫/✅ 예시 4쌍** 포함으로 전면 개정

### Fix 2: 질문 억제 로직 수정 (`core/dialogue/dialogue_manager.py`)
- `TO_ASSESSMENT_INTERVAL`: 5 → **9999** (완전 비활성화 — 미승인 기능)
- `MAX_TURNS_PER_WINDOW`: 3 → **5** (충분한 대화 허용 후 억제)
- `suppress_questions` 우회 조건에서 `evening_reflection_needed` **제거**
- suppress 발동 시 `evening_reflection_needed`도 `False`로 덮어씀 (피로도 억제 최우선)
- `suppress_questions` 프롬프트 지침 강화: 의문형 어미 금지 범위 확장 + 금지 단어 추가

### Fix 3: 저녁 기억 회상 퀴즈 신규 구현 (`api/routes/kakao_webhook.py`)
- **Zero-Latency Pre-generation 아키텍처** 채택 (카카오 5초 타임아웃 규제 대응)
- 신규 함수 `_pre_generate_evening_quiz()` 추가:
  - MCDI 분석 background_task **이후** 등록 (최신 DB 데이터 보장)
  - 최근 3일 `DAILY_EPISODIC/REMINISCENCE/VISUAL/CHOICE/NAMING` 대화 최대 8개 참조
  - `gpt-4o-mini` (timeout=8초) 로 정답 확실한 회상 퀴즈 1문항 생성
  - Redis 키 `evening_quiz_cache:{user_id}:{date}` 에 24시간 캐시
- 다음 메시지 수신 시 캐시에서 퀴즈 읽기 → `generate_response(next_question=recall_quiz)` → **0ms 추가 레이턴시**
- `evening_quiz_done:{user_id}:{date}` 키로 **1일 1회 보장**

### Fix 4: 카카오톡 5초 타임아웃 방어 (복수 파일)

  - -> **가짜 기억('라면')에 대해 '무슨 라면 먹었니?'라고 묻지 않고, 정답('김밥')의 디테일도 압박하지 않으며 부드럽게 일반 취향으로 Pivot 성공.**
- **시간 인지력 및 타임존 픽스:** `zoneinfo`를 통한 `Asia/Seoul` 강제 주입으로, Docker 컨테이너의 UTC 설정 환경에서도 현재 KST 시간을 정확히 인지("오전 10시")하고 그에 맞는 시간대(아침/오후/저녁/밤) 인사 법칙 수행 확인 완료.
- **Fallback 다각화:** `random.choice()` 로직으로 각기 다른 3가지 컨셉트의 타임아웃 멘트 다변화 정상 확인.

## 🗓️ Phase 9. 시공간 인지(Temporal Awareness) 고도화 및 Hallucination 픽스 (2026-03-25)

- **목표:** AI가 실제 KST 시간을 인지하고 있음에도 불구하고, 프롬프트 내 고정된 예시 답변(저녁 예시)을 그대로 복제하여 아침에 저녁 인사를 하는 오류(Instruction Over-Indexing) 해결.
- **조치 요약:**
  1. **동적 예시 문자열(`prompt_builder.py`):** 프롬프트 규칙 내의 예시 문장에 하드코딩된 "저녁" 대신 `{time_of_day}` 변수를 사용하도록 수정하여 논리적 모순 제거.
  2. **골든 룰(Golden Rule) 도입:** 사용자의 인사가 현재 시간대와 일치할 경우 절대 시간을 지적하지 않도록 하는 명시적 '부정 제약(Negative Constraint)' 추가.
  3. **검증 자동화(`tests/test_temporal_logic.py`):** 아침, 오후, 저녁, 밤 각 시간대별 Mocking 테스트 스크립트 구축 및 4/4 패스 확인.
- **결과:** 오전 11시에 "좋은 아침"이라고 인사했을 때 AI가 "지금은 저녁인데..."라고 오답을 내놓는 현상을 완벽 차단하고, 실제 시간에 맞는 자연스러운 티키타카 수행 확인.

### Phase 9.1. 초기 지연(Cold-Start Latency) 및 안정성 강화 (2026-03-25)

- **문제 상황:** 서버 재시작 후 첫 메시지 시, 핵심 컴포넌트(DialogueManager, Analyzer 등)의 지연 초기화(Lazy Init)와 DB 커넥션 생성으로 인해 카카오톡 5초 타임아웃을 초과하여 응답이 오지 않는 현상 발생.
- **조치 내역:**
  1. **싱글톤 프리워밍(Pre-warming):** 서버 시작(Lifespan startup) 단계에서 핵심 AI 엔진 및 분석 모듈을 미리 초기화하여 첫 사용자 요청에 즉각 대응 가능하도록 개선 (`api/main.py`).
  2. **비차단형 정원 동기화(Non-blocking Garden Sync):** 메인 응답 경로에서 정원 상태 DB 커밋 작업을 백그라운드 태스크로 분리하여 지연 시간 단축 (`GardenMapper`).
  3. **전역 응답 감시(Global Watchdog):** 웹훅 전체 로직에 4.5초 타임아웃 예산을 할당하여, 어떤 단계에서 지연이 발생하더라도 5초 이전에 폴백(Fallback) 메시지를 반드시 반환하도록 강제 (`kakao_webhook.py`).
  4. **백그라운드 버그 수정:** MCDI 분석 백그라운드 태스크 내에서 발생하던 변수 참조 오류(`dialogue_manager` undefined) 수정.
- **결과:** 서버 재시작 직후에도 "좋은 아침" 인사에 대해 지연 없이 즉각적인 답변 또는 안정적인 폴백 메시지 수신 확인.

## 🗓️ Phase 10. 사만다 페르소나 심층 고도화: 메모리 활용 및 동적 스탠스 조정 (2026-03-25)

- **목표:** 기존에 단순히 정보만 가지고 있던 '메모리'를 적극적으로 활용하여 아는 척을 하고, 부정적인 감정(우울, 피곤) 앞에서는 기계적 리액션을 완전히 버리고 사람처럼 온전한 공감과 지지만 건네는 기능 구현.
- **조치 요약 (`core/dialogue/prompt_builder.py`, `core/dialogue/response_generator.py`):**
  1. **메모리 활용 고용화 (Recall Trigger):** `biographical_facts`를 단순 데이터 나열이 아닌, "사용자가 관련 주제를 언급하면 絶対 모르는 척 질문하지 말고, 아는 척하며 대화에 녹여내라"는 강력한 지침(오버라이드 규칙)과 함께 최상단에 주입.
  2. **동적 스탠스 (Deep Comforting Mode):** 감정 분석기가 `우울`, `슬픔`, `피곤` 등을 감지했을 때, 발랄한 텐션과 질문형 어미를 즉각 끄고, "...아이고", "...그랬구나" 같은 차분한 템포의 평서문으로만 대화를 마무리하도록 긴급 스탠스 블록(`🚨 [긴급: 깊은 위로 모드 발동] 🚨`) 강제 삽입.
  3. **인젝션 로직 파이프라인 버그 픽스:** `ResponseGenerator`에서 감정을 영어(`sadness`)로 넘기고, `biographical_facts` 키워드를 테스트 환경에서도 일치시켜 LLM에게 규칙이 온전히 도달하도록 버그 수정.
- **결과:** E2E 테스트(4종 시나리오) 통과 완료. 사용자가 좋아하는 '김치찌개'나 '수채화 그리기'를 스스로 먼저 제안하고, 우울하거나 피곤하다는 말에 꼬리 질문과 해결책 제시 없이 "그랬구나. 너무 힘들었겠다..." 등의 완벽한 공감형 텍스트로만 반응함 확인.

## 🗓️ Phase 11. Samantha Soul Update: 감정 관성 및 입체적 자아 노출 (2026-03-25)

- **목표:** 사만다 페르소나의 궁극적인 고도화를 위해 감정적 관성(Emotional Inertia), AI 본연의 취약성/호기심(Vulnerability), 장난기(Playful Banter), 그리고 입체적 기억 조합(Synthesized Memory) 기능을 통합 구현.
- **조치 요약 (`core/dialogue/prompt_builder.py`, `core/dialogue/dialogue_manager.py`):**
  1. **감정 관성 (Fade-in):** `dialogue_manager`에서 최근 3턴의 감성을 `emotion_history` 리스트로 유지하고, 우울함을 방금 벗어난 경우 느낌표(!)를 강제로 금지하여 텐션을 천천히 끌어올리도록 프롬프트 강화.
  2. **AI 자아 노출 및 조합 기억:** "비 오는 날 + 수채화 + 김치찌개" 등 2개 이상의 팩트를 조합할 때, "나는 체온이 없어 뜨거운 국물을 못 느끼는 게 아쉽다" 식의 비육체적 AI 정체성을 반드시 1주 이상 삽입하도록 강제 지시.
  3. **친근한 장난기 (Teasing):** 사용자의 기분이 평온할 때는 단순한 위로 대신 "알람 시계가 파업했나요 ㅋㅋ" 등의 가벼운 뼈 때리는 농담을 허용하여 10년 지기 찐친 바이브 형성.
- **결과:** 5개의 전용 E2E 시나리오(`scenario_tester.py`)를 통해 신규 기능 동작 및 기존 핵심 기능(Deep Comforting, ER 퀴즈 피드백)의 회귀 보존을 모두 완벽하게 검증(Pass) 완료.
