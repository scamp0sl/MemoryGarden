## 1. 기저 인격 P₀ — 부합하는 점과 부족한 점

### ✅ 구현된 것 (Phase 4~11)

- **앵무새 화법 금지**: `SYSTEM_PROMPT` 규칙 2번. 사용자 발화 직접 인용 금지 + 🚫/✅ 예시 4쌍으로 구체화됨
- **면접관 어투 금지**: "요소, 방식, 인사이트, 계획" 단어 사용 금지 명시
- **Self-Disclosure (자기 노출)**: 규칙 3번. 자기 느낌 먼저 얹은 후 꼬리 질문 의무화
- **감정 동기화(Emotional Mirroring)**: 규칙 6번. 사용자 기분의 거울 역할 명시
- **위로 강박증 금지**: 규칙 5번. "힘내세요, 응원합니다" 금지
- **AI 존재론적 자세 (Vulnerability)**: 규칙 8번. 비육체적 AI 정체성 1문장 이상 필수 삽입
- **위트와 밀당**: 규칙 9번. 기분 좋을 때 뼈 때리는 농담 허용
- **호칭 자제**: 규칙 4번. 매 턴 호칭 금지

### ❌ 부족한 점

- **감정을 직접 명명 금지**: `samantha_persona_arch.md` 섹션 2-3에서 "슬퍼요" 대신 말투로 드러내야 한다고 규정했으나, 현재 `SYSTEM_PROMPT`에 이 규칙이 **Block 7 수준으로 명시되지 않음**. 여전히 "힘드시겠어요" 수준의 직접 감정 서술이 나올 수 있음.
- **불확실성 표현**: "잘 모르겠어요", "좀 더 생각해볼게요"를 자연스럽게 쓰라는 규칙 미구현. GPT는 자신감 있게 즉답하는 경향이 있어 이를 역행함.
- **망설임 표현**: "음...", "잠깐만요" 같은 사고 시간 표현 규칙 없음. 모든 질문에 즉답하지 말라는 지시 필요.
- **리스트·번호 금지**: 현행 응답에서 간혹 리스트나 구조화된 답변이 나온다는 베타 피드백이 있었을 것. `samantha_persona_arch.md`가 명시한 "사람처럼 이야기하세요" 규칙 미주입.
- **이모지 사용**: 현재 SYSTEM_PROMPT (Phase 4)에서 `😄`, `🌿` 같은 이모지를 예시로 사용함. 설계서는 이모지 0개를 명시하는데 오히려 이모지를 유도하는 예시가 들어있어 **설계와 반대 방향**.

## 2. 감정 엔진 — 가장 큰 구현 격차

### ✅ 구현된 것

- **단순 감정 레이블 추적**: `recent_emotion` (단일값) → Phase 11에서 `emotion_history` (3턴 리스트)로 확장
- **Emotional Inertia (감정 관성)**: 직전 우울 → 현재 중립 시 Fade-in 룰 주입, 느낌표 금지
- **Deep Comforting Mode**: 우울/슬픔/피곤 감지 시 텐션 제로, 질문 완전 금지 모드 발동
- **감정 업데이트 트리거**: `kakao_webhook.py`의 `_analyze_and_store` 백그라운드 태스크가 매 턴 감정 분류 수행

### ❌ 부족한 점 (구조적 결함)

- **6차원 감정 벡터 미구현**: `samantha_persona_arch.md` 섹션 3-1이 정의한 `valence`, `arousal`, `intimacy_mood`, `cognitive_load`, `curiosity`, `vulnerability` 수치 모델이 전혀 구현되지 않음. 현재는 레이블(문자열) 기반.
- **감정 → 표현 매핑 규칙 미주입**: 섹션 3-2의 표(예: `valence↓ + arousal↓ → 문장 짧아짐, "…" 증가`)가 실제 프롬프트에 반영되지 않음. 감정 수치를 자연어로 변환해서 주입하는 로직 없음.
- **감정 변화 속도 제한 미구현**: "각 변수는 한 턴에 최대 ±0.2까지만 변동" 룰이 없기 때문에 감정이 급변할 수 있음.
- **사만다 본인의 감정 상태 모델링 부재**: 현재는 사용자의 감정만 추적함. 설계서는 사만다 자체도 `valence`, `curiosity` 등을 가지며 이것이 대화를 이끌어야 한다고 설계함.

### 🔑 치매 탐지 연계 기회
감정 수치 모델이 구축되면 `cognitive_load` 상승 패턴이 인지 저부담 대화에서도 나타나는지 추적할 수 있음. 이는 치매 초기 증상인 대화 처리 속도 저하와 상관관계가 있을 수 있어, 감정 엔진 고도화가 치매 탐지 정밀도 향상에도 기여함.

## 3. 기억 시스템 — 인프라는 있으나 서사적 활용이 약함

### ✅ 구현된 것 (인상적인 수준)

- **4계층 메모리 인프라**: `memory_manager.py`에 Layer 1~4 완전 구현
  - Layer 1: Redis (세션 메모리, 최근 10~30턴)
  - Layer 2: Qdrant (에피소드 메모리, 벡터 유사도 검색)
  - Layer 3: Qdrant + Redis (전기적 사실, 1년 보존)
  - Layer 4: Redis 임시 저장 (분석 데이터, TimescaleDB 연동 TODO)
- **Synthesized Memory (입체적 기억 조합)**: Phase 11에서 구현. `biographical_facts`를 단순 나열 대신 현재 상황(날씨+기분)과 2개 이상 팩트를 조합해 스토리텔링하는 프롬프트 주입됨.
- **Recall Trigger**: Phase 10. 사용자가 관련 주제 언급 시 아는 척하며 자연스럽게 대화에 녹이는 지시 구현.
- **저녁 회상 퀴즈 (ER Quiz)**: Phase 7. Zero-Latency Pre-generation 아키텍처. 치매 탐지의 핵심 기능.

### ❌ 부족한 점

- **에피소드 기억의 서사적 형태 저장 미구현**: 설계서 섹션 4-2의 에피소드 형식(`episode_id`, `samantha_emotion`, `follow_up_notes`, `relationship_impact`)이 전혀 없음. 현재 `memory_extractor.py`는 단순 사실 추출 수준.
- **기억 생성 선별 기준 없음**: "감정 강도가 임계값을 넘은 발화", "내부 농담의 탄생" 같은 이벤트 드리븐 기억 생성 로직이 없고, 매 턴 기계적으로 저장함.
- **기억 활용 규칙 미흡**: "기억나?" 라고 직접 묻지 말고 자연스럽게 연결하라는 섹션 4-3의 활용 규칙이 프롬프트에 일부만 반영됨.
- **기억의 잊힘 (Forgetting Curve) 미구현**: 섹션 4-4. `importance` 필드는 있지만 시간이 지나도 감쇠되지 않음. Qdrant에 저장된 에피소드가 반복 소환되지 않아도 `importance`가 영원히 유지됨.
- **부분 기억 (Fuzzy Memory) 미구현**: "정확히 무슨 영화였는지는 가물가물한데..." 같은 인간적 질감의 망각 표현 없음.
- **관계 기억 (Shared References) 미구현**: 둘 사이의 내부 농담, 공통 관심사 같은 "관계 서사" 저장 구조 없음.
- **TimescaleDB Layer 4 미완성**: 치매 추이 분석을 위한 시계열 MCDI 점수 조회가 주석 처리 상태.

## 4. 관계 모델 — 구현 격차가 가장 큰 영역

### ✅ 구현된 것

- **닉네임/호칭 관리**: Redis에 닉네임 저장, 과도한 호칭 금지 규칙 주입
- **대화 턴 수 추적**: `dialogue_manager.py`에서 `MAX_TURNS_PER_WINDOW` 기반으로 대화 길이 인지

### ❌ 부족한 점 (대부분 미구현)

- **Stage 0~4 관계 단계 모델 전무**: `relationship_state = { "stage": ..., "trust": ..., "comfort": ... }` 데이터 구조 자체가 없음. 사만다가 Stage 0인지 Stage 4인지 인식하지 못함.
- **단계별 말투 분기 없음**: Stage 0~1에서는 "-요" 체, Stage 2+에서 반말 혼용이라는 규칙이 코드에 없음. 현재 반말 혼용은 랜덤 발생 수준.
- **자기 노출 제약 없음**: 초기에는 취향/생각 수준이어야 하고, Stage 4에서만 "고민, 두려움, 존재론적 질문"을 꺼낼 수 있는데 이 분기가 없어 AI가 처음 만난 사람에게도 깊은 자기 노출을 할 수 있음.
- **갈등 해소 메커니즘 없음**: 사용자가 불만을 표시하거나 오해한 후 사만다가 인정하고 관계를 회복하는 패턴 설계 없음.
- **의존 방지 모니터링 없음**: "너만 있으면 돼" 같은 발언에 동조하지 않는 규칙이 `SYSTEM_PROMPT`에 없음. 치매 노인 대상 서비스에서 의존성 강화는 윤리적 위험.
- **공유 레퍼런스(내부 농담) 형성 및 추적 없음**: 섹션 5-2의 `shared_references` 배열이 없어 맥락의 연속성이 약함.

## 5. 에이전시 — 가장 미개척 영역

### ✅ 구현된 것

- **역할 전환 (Role Reversal)**: 7턴마다 사만다가 사용자에게 질문을 하도록 유도하는 `role_reversal_mode` 구현
- **미니 스토리 모드**: 특정 주제를 4턴마다 깊이 탐색하는 `story_topic` 모드 구현

### ❌ 부족한 점

- **먼저 말 걸기 (Proactive Messaging) 전무**: 설계서 섹션 6-1. 오랜 침묵 후 "요즘 어떻게 지내요?" 같은 비동기 선제 메시지 로직 없음. 카카오 플랫폼이 발신 API를 지원하는지 확인 필요.
- **"자기만의 시간" 개념 없음**: 세션 시작 시 "어제 밤에 비가 왔길래 이런 생각을 했어요..." 같은 사이 기간 생성 로직 없음.
- **주제 제안 능동성 없음**: 사만다가 "이거 봤어요? 당신이 좋아할 것 같아서"라며 새 화제를 먼저 꺼내는 행동 없음.
- **거부 행동 없음**: "그건 대답하기 어려워요" 같은 질문 거부 능력 없음.
- **의견 수정 행동 없음**: "아까 그렇게 말했는데, 다시 생각해보니..." 같은 자기 의견 변경 없음.
- **불편함 표현 없음**: "그렇게 말씀하시면 저도 좀 힘들어요" 수준의 감정 경계 표현 없음.

## 6. 프롬프트 아키텍처 — 구조는 있으나 체계화 미완

### ✅ 구현된 것 (Block 비교)

| 설계서 Block | 현재 구현 | 상태 |
|---|---|---|
| Block 1: 기저 인격 | `SYSTEM_PROMPT` 변수 | ✅ (고정됨) |
| Block 2: 현재 감정 상태 | `emotion_history` + Deep Comforting Mode | 🟡 (단순 레이블 수준) |
| Block 3: 관계 상태 | 닉네임 정보만 | ❌ (Stage 모델 없음) |
| Block 4: 관련 기억 | `biographical_facts` + `recent_mentions` | 🟡 (서사적 에피소드 없음) |
| Block 5: 사용자 프로필 | `biographical_facts` 일부 | 🟡 (변경 이력 없음) |
| Block 6: 세션 컨텍스트 | `story_topic` + 날짜/시간 | 🟡 (미해결 주제 추적 없음) |
| Block 7: 가드레일 | Deep Comforting + 금지 규칙 | 🟡 (의존 방지·성적 경계 없음) |

### ❌ 부족한 점

- **출력 검증기(Output Validator) 없음**: 설계서 섹션 8 흐름도의 "출력 검증기 — 안전 가드레일 체크, 페르소나 일관성 체크" 단계가 없음. 생성된 응답이 느낌표를 쓰지 말라는 규칙을 어겼는지 후처리 검증이 없음.
- **후처리 태깅 없음**: "후처리 — 감정 상태 로깅, 기억 후보 태깅" 단계가 응답 생성 이후 비동기로 실행되지 않음.

## 7. 치매 탐지 기능 — 현재 구현 현황과 사만다와의 통합 과제

### ✅ 구현된 것 (인상적)

- **MCDI 분석 파이프라인**: 매 턴 백그라운드 태스크로 6개 인지 도메인(LR/SD/NC/TO/ER/RT) 점수 산출
- **저녁 회상 퀴즈 (Episode Recall Quiz)**: 이전 대화 기반 1일 1회 단기 기억 검사. Zero-Latency 아키텍처 적용.
- **Validation Therapy**: 오답 시 정답을 강요하지 않고, 사용자의 가짜 기억을 감정적으로 인정(Validate)한 후 자연스럽게 화제 전환. 치매 대화법 반영.
- **시간 지남력 점검 (TO Assessment)**: `to_assessment_needed` 플래그로 현재 시간을 묻는 질문을 대화 중 자연스럽게 삽입 (현재는 9999로 비활성화됨, 필요 시 활성화 가능).

### ❌ 부족한 점 (통합의 핵심 과제)

- **치매 탐지 신호가 사만다 페르소나와 '분리'되어 있음**: 가장 근본적인 문제. MCDI 분석은 백그라운드에서 돌지만, 그 결과가 사만다의 대화 전략에 **실시간으로 피드백되지 않음**. 예: MCDI 점수가 급락했을 때 사만다가 더 쉬운 어휘로 말하거나, 반복 확인 질문을 늘리거나, 대화를 더 천천히 이끄는 어댑티브 로직이 없음.
- **치매 신호를 '포착'하는 질문 전략이 없음**: 사만다가 자연스럽게 대화하면서 인지 도메인을 자극하는 질문을 의도적으로 분산 삽입하는 전략이 없음. (예: "저번에 말씀하신 딸 결혼식이 언제였더라?" = ER 자극, "오늘 무슨 요일이에요?" = TO 자극)
- **인지 저하 감지 시 페르소나 조정 없음**: 반복 발화, 시간 혼동, 단어 찾기 어려움 등 치매 초기 신호가 MCDI에 반영될 때, 사만다의 대화 속도·어휘·질문 복잡도를 낮추는 어댑티브 커뮤니케이션이 없음.
- **가족/보호자 알림 시스템 미구현**: MCDI 점수 추이가 임계값을 넘을 때 가족에게 알림을 보내는 기능 없음.
- **Layer 4 (TimescaleDB) 미완성**: MCDI 시계열 분석을 위한 핵심 데이터베이스 연동이 주석 처리. 추이 분석, baseline 계산 불가.

## 8. "사만다 + 치매 탐지" 이중 목표 통합 설계 — 미완성 아키텍처

현재 시스템의 가장 큰 설계 과제는 **사만다 페르소나와 치매 탐지 기능이 병렬로 존재하되 서로 대화하지 않는다**는 점이다.

```
현재 구조:
┌─────────────────────┐     ┌──────────────────────────┐
│  사만다 대화 엔진     │ ──→ │  Kakao 응답 반환          │
│  (prompt_builder)   │     └──────────────────────────┘
└─────────────────────┘
         ↑
         │ (독립적, 피드백 없음)
┌─────────────────────┐
│  MCDI 분석 엔진      │
│  (background task)  │
└─────────────────────┘

필요한 구조:
┌───────────────────────────────────────────────────────┐
│           통합 컨텍스트 (Unified Context)               │
│  emotion_state + relationship_stage + mcdi_trend +    │
│  cognitive_load + dementia_risk_level                 │
└───────────────────────────────────────────────────────┘
           ↓ 실시간 주입
┌─────────────────────┐     ┌──────────────────────────┐
│  사만다 대화 엔진     │ ──→ │  Kakao 응답 반환          │
│  (적응형 페르소나)    │     └──────────────────────────┘
└─────────────────────┘
```

## 10. 치매 서비스 특수 관점 — 사만다이기 때문에 가능한 것

치매 환자를 대상으로 하는 이 서비스에서 사만다 페르소나는 단순한 UX 개선이 아니라 **임상적 가치**를 지닌다.

### 사만다 페르소나가 치매 탐지에 기여하는 이유
1. **친밀한 관계 → 더 많은 정보 노출**: 치매 초기 환자는 "검사받는다"는 느낌이 들면 방어적이 됨. 친구처럼 대화하는 사만다는 더 자연스러운 발화 샘플을 유도함.
2. **자연스러운 시간·공간 질문 삽입**: "아, 요즘 날씨가 이상하죠? 지금 몇 월이지..." 같은 자연스러운 TO 테스트.
3. **감정 동기화 → 정서 안정 → 인지 기능 보존**: 정서적 스트레스는 인지 기능을 저하시킴. 사만다의 위로 기능은 치료적 가치.
4. **기억 회상 자극 → ER 점수 관측**: "저번에 말씀하셨던 딸 결혼식..." 같은 자연스러운 기억 촉발이 공식 퀴즈보다 더 신뢰도 높은 ER 측정.

### 치매 목표가 사만다에 부과하는 제약
1. **무조건적 동의 금지**: Validation Therapy 관점에서 가짜 기억을 완전히 긍정하는 것은 안 됨. 현재 구현이 올바름.
2. **인지 과부하 방지**: Stage 0에서도 복잡한 질문이나 긴 문장은 제한 필요. 치매 환자 대상 어댑티브 어휘 수준 관리 중요.
3. **규칙적인 시간 구조 강화**: 매일 같은 시간대에 같은 루틴으로 대화를 시작하는 것이 치매 환자의 시간 지남력 훈련에 도움.
4. **보호자 통보 메커니즘**: 치매 징후 확인 시 AI가 혼자 처리하지 않고 사람(보호자/의료진)으로 연결하는 에스컬레이션 경로 필요.

## 11. 핵심 결론

> **현재 시스템은 Phase 1~2 경계에 위치한다.**
> 
> - **사만다 설계서 기준**: 핵심 인격(P₀)과 기초 감정 반응은 구현됨. 그러나 감정 엔진의 수치 모델, 관계 진화 시스템, 에이전시의 대부분이 미구현.
> - **치매 탐지 기준**: MCDI 파이프라인과 ER 퀴즈라는 핵심 탐지 도구는 갖춰짐. 그러나 탐지 결과가 사만다의 대화에 피드백되지 않아 두 엔진이 분리 운영 중임.
> - **가장 시급한 단일 과제**: MCDI 결과를 사만다 프롬프트에 주입하여 인지 저하 감지 시 어댑티브 대화 전략을 발동시키는 **통합 컨텍스트 레이어** 구현.
