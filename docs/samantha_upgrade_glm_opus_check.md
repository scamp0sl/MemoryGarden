### TASK-01: SYSTEM_PROMPT 존재론적 재설계

#### ⚠️ **[위험: HIGH] 기존 규칙의 핵심 가치가 희석될 위험**

**문제점 1: 규칙 번호 매기기 폐지의 부작용**

문서에서는 "규칙 번호 매기기 (1, 2, 3...) — 체크리스트 느낌"을 제거하라고 합니다.

```python
# 기존 (prompt_builder.py:102-111)
## 🚨 절대 규칙 (위반 시 강제 종료) 🚨
1. **면접관/상담사/기계적 어투 절대 금지**: ...
5. **응답 길이 엄격 제한**: 답변은 반드시 **한두 문장, 공백 포함 100자 이내**로 작성하세요.
```

하지만 규칙 번호는 "체크리스트 느낌"을 주는 것 이상의 역할을 합니다:
- **우선순위 명확화**: 금지 규칙 vs 가이드 규칙의 차이
- **참조 가능성**: 문제가 발생했을 때 "규칙 #5 위반"으로 로깅/디버깅 가능
- **LLM의 해석 안정성**: Claude와 같은 LLM은 번호 매겨진 리스트를 더 잘 따르는 경향

**위험도**: `HIGH` — 응답 길이 제한(규칙 #5)이 제거되면 MCDI 수집의 품질이 직접적 위험입니다.

**문제점 2: "침묵"과 "망설임"의 혼재**

기존:
- 규칙 #7: "망설임과 불확실성 표현 (인간다움의 핵심)"
- 규칙 #3: "진짜 친구 같은 티키타카"

문서의 새 구조:
```python
## 자연스러운 대화의 기술
...
**침묵**: 대답을 이어가기 위해 무리하지 마세요. "..."이나 짧은 감탄으로 충분할 때가 있습니다.
```

이렇게 "망설임"을 "침묵"으로 통합하면 구분이 모호해집니다:
- 망설임: "음...", "잠깐만요...", "글쎄요..." (생각 중)
- 침묵: "...", "..." (감동, 말 없는 리액션)

둘은 다른 목적과 용도를 가집니다.

**위험도**: `MEDIUM` — LLM이 망설임과 침묵을 혼동하여 부적절한 응답을 생성할 수 있습니다.

**문제점 3: "길이는 그때그때 달라요"의 모호함**

문서의 제안:
```python
# 길이는 그때그때 달라요:
# - 감동받았거나 진지한 이야기: 짧게, 한 문장으로
# - 재밌는 이야기나 자기 경험: 조금 길어도 괜찮아요
# - 할 말 없을 때: "...", "음...", "ㅎㅎ" 하나로 충분
```

이 지침은 너무 모호합니다. LLM에게 있어서 "감동받았을 때"와 "재밌을 때"의 구분은 명확하지 않습니다.

**실제 위험 사례**:
```
사용자: "남편이 돌아가셨어요"
감동 상황 → 문서 지침에 따르면 "짧게, 한 문장으로"
사만다: "..." (하나도 안 함)
```

이는 MCDI의 서사 분석(SD 지표)을 무력하게 만듭니다.

**위험도**: `CRITICAL` — 응답 길이가 MCDI 데이터 품질의 핵심 요소입니다.

---

#### 💡 **[제안] 절축안**

1. **규칙 번호는 유지하되되, 섹션명을 개선**:
   ```python
   ## 🚨 절대 규칙 (위반 시 강제 종료) 🚨
   ```
   →
   ```python
   ## 반드시 지켜주세요
   ```

2. **응답 길이는 명확한 범위로 유지**:
   ```python
   ## 응답 길이
   - 기본: 1~2문장, 50~150자
   - 깊은 감정(슬픔, 감동): 1문장, 30~80자
   - 재밌는 이야기: 2~3문장, 100~200자 (최대)
   - 절대 금지: 리스트 형식, 5문장 이상, 300자 이상
   ```

3. **망설임과 침묵을 분리**:
   ```python
   ## 망설임 (생각 중인 표현)
   - 모르는 것: "글쎄요...", "잘 모르겠어요"
   - 생각 정리: "음...", "잠깐만요..."

   ## 침묵 (할 말 없을 때)
   - 감동받음: "..."
   - 긍정적 부정: "ㅎㅎ", "ㅠㅠ"
   ```

### TASK-02: 감정 시스템 — 관찰에서 공명으로

#### ⚠️ **[위험: MEDIUM] 감정 벡터 6차원 확장의 구현 난이도**

문서에서는 EMOTION_VECTOR_MAP을 3차원에서 6차원으로 확장하려고 합니다:

```python
# 기존 (dialogue_manager.py:51-72)
"기쁨": (0.8, 0.6, 0.1),  # (valence, arousal, intimacy)

# 신규 제안
"기쁨": (0.8, 0.6, 0.1, 0.0, 0.3, 0.2),  # (+ cognitive_load, curiosity, vulnerability)
```

**구현 문제**:

1. **기존 코드와의 불일치**: `prompt_builder.py:479-517`에서는 `"v"`, `"a"`, `"i"` 키만 사용하고 있습니다. 6차원 확장을 위해서는 이 부분도 수정해야 합니다.

2. **Redis 데이터 호환성**: 현재 Redis에 저장된 감정 벡터는 3차원 형태입니다. 6차원으로 확장하면:
   - 기존 사용자의 Redis 데이터를 마이그레이션해야 함
   - 또는 하위 호환성을 유지하는 fallback 로직 필요

3. **의미 중복**:
   - `cognitive_load`와 `arousal`이 상관관계 (높은 arousal → 높은 cognitive_load)
   - `vulnerability`와 `intimacy`이 상관관계

**위험도**: `MEDIUM` — 복잡도가 크게 증가하는데 비해 실제 효과가 불확실합니다.

---

#### 💡 **[제안] 절축안**

6차원 확장 대신 **기존 3차원 체계 내에서 자연어 변환을 개선**하세요:

```python
# 기존 (prompt_builder.py:487-513)에서 이미 충실하게 구현됨
if v > 0.5:
    desc_parts.append("기분이 밝고 긍정적이에요")
```

### TASK-03: 동적 응답 길이 & 리듬 시스템

#### ⚠️ **[위험: HIGH] 응답 길이를 너무 크게 허용**

문서에서는 `max_tokens`를 80~300으로 동적으로 조정하려고 합니다:

```python
# 기존
DEFAULT_MAX_TOKENS = 150

# 신규 제안
return max(80, min(300, base))
```

**문제점**:

1. **300 토큰은 너무 깁니다**: 한글 300 토큰은 약 600-800자에 달합니다. 이는 "짧은 응답"이라는 사만다의 핵심 특성을 위반합니다.

2. **Claude의 특성**: Claude(특히 Sonnet)는 긴 응답 생성 경향이 있습니다. max_tokens를 300으로 늘리면 대부분의 응답이 200-300 토큰에 도달할 것입니다.

**위험도**: `HIGH` — 사만다의 "짧고 간결한" 특성이 사라집니다.

---

#### 💡 **[제안] 절축안**

```python
# 더 보수적인 범위 설정
```

### TASK-06: 관계 진화에 따른 대화 깊이 계층화

#### ⚠️ **[위험: MEDIUM-HIGH] 반대 의견 허용의 위험**

문서에서는 Stage 3+에서 "사만다가 사용자에게 조언이나 의견 제시도 가능"이라고 합니다:

```python
elif stage >= 4:
    parts.append("- 사용자의 결정에 명확하게 반대할 수 있음 (단, 항상 존중은 유지)")
```

**치매 탐지 서비스에서 이는 위험할 수 있습니다**:

1. **치매 환자의 혼란**: 사용자가 이미 인지적 어려움을 겪고 있을 때, 사만다가 "반대 의견"을 제시하면 사용자가 더 혼란스러워질 수 있습니다.

2. **의학적 조언의 위험**: 예를 들어:
   ```
   사용자: "요즘 잠이 안 와서 약 먹어야 할 것 같아요"
   사만다 (Stage 4): "음... 솔직히 약은 좀 신중하게 생각해보세요. 부작용이 있을 수 있어요."
   ```
   이는 의학적 조언이 될 수 있습니다.

**위험도**: `MEDIUM-HIGH` — 윤리적, 의학적 리스크가 있습니다.

---

#### 💡 **[제안] 절축안**

```python
elif stage >= 3:
    parts.append("- 깊은 이야기, 솔직한 감정 표현 자유롭게")
    parts.append("- 가끔 자기 이야기도 꺼낼 수 있음")
    # 반대 의견 제시는 제외하거나 매우 조심스럽게
    parts.append("- 단, 사용자의 결정이나 선택에 대해서는 존중하고 지지해 주세요.")
```
